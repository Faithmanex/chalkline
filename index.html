The design board

Draw it once, hand it to the cutter.

Chalk, line, arrow, note, erase. Five chalk colours. A garment form faint enough to draw over, and a grid that snaps to the same spacing as pattern paper.

Drop a measurement pin and it binds to the client's real number — Bust 38" stays on the bust, not floating somewhere near it. Pins, strokes and notes are saved as vectors against the order, so the sheet comes back exactly as it was left.

Export the sheet as a PNG for a WhatsApp message, or print it into the order ticket at full fidelity.

One drawing, three outputs

The screen, the PNG, the ticket.

Because the sheet is stored as vectors in a fixed space, the drawing that shows on a laptop at 11am is the same drawing that goes out on paper at 4pm — and the whole design costs a few kilobytes, not a few hundred.

A pin never stores a number, only a reference to the client's measurement for that garment. Re-measure a waist and every sheet that pinned it follows.

Getting booked

The link you send instead of explaining your hours.

Each shop gets a booking page that knows its opening hours, its closing day, its slot length, and which slots are already gone. A booking that arrives is unanswered until the shop says yes — so a request never looks like a promise.

From the booking, one dialog makes the order: garment, price, deposit, due date. The client book is created with the measurements already attached, and the appointment is marked converted.

The two things a shop is asked about

What is owed, and what is on the paper
Money

Know what is owed before you ask for it.

Every order carries a total, a deposit and a ledger of payments. The board totals the balances, the money screen shows six months of collection, and a client card says what that name still owes — in red, in mono, at the size money deserves.

Measurements

A client's numbers, per garment, with history.

Measurements are stored per person and per garment, in inches or centimetres, converted on the way in and never overwritten — a new entry is a new date. A twelve-year-old customer's first shirt measurements are still there when he comes back for a blazer.

How it is built

No framework, no build step, no server
Stack
Vanilla ES modules in UMD factories, one stylesheet, one canvas renderer. Open the folder and it runs.
State
Everything in localStorage, with a JSON backup and restore. No account, no network call, no telemetry.
Tests
30 node:test cases over the domain (money, stages, booking collisions, unit conversion) and the canvas geometry.
Drawing
Strokes stored as vectors in a fixed 1000 × 1400 space, so screen, export and print are the same drawing.
Print
A real print stylesheet: one ticket per garment on A4, with the design PNG embedded as a data URL.
Money
Integer-safe totals and a payment ledger per order. The board's "owed to you" is the sum of balances, not a separate number.
